## A. C1 — 개행·인코딩 규격

```
C1: <해결 | 미해결>
```

1. 디스크 개행이 **LF(`0x0A`) 하나로 고정**됐는가. `println`·`PrintWriter` 금지가 명시됐는가
2. UTF-8 디코딩 실패 시 처리(strict 디코딩 → `CORRUPT`, 원시 바이트는 `runs/` 에 보존)가 정의됐는가
3. 이 규격으로 헤더 개행과 닫는 마커 앞 개행의 바이트 수가 **한 가지로만 해석되는가**

## B. C2 — 재동기화 조건 강화와 약속 하향

```
C2: <해결 | 미해결>
```

1. 조건이 `id > last_id` 에서 **`id == last_id + 1`** 로 바뀌었는가
2. **`id < room.properties` 의 `next_id`** 조건이 추가되고, `next_id` 유지가 규칙에 명시됐는가
3. **약속 수준이 낮아졌는가** — "손상 뒤 나머지를 정상 복원한다" → "복구를 시도하며 복구분은 `SUSPECT` 로 표시한다"
4. **강화된 조건으로도 반례가 남는다는 사실이 문서에 정직하게 적혀 있는가.** 네가 3라운드에서 제시한 반례가 완전히 막혔다고 문서가 주장하고 있으면 그것은 미해결이다
5. **손상되지 않은 파일의 무손실 왕복이 재동기화와 무관하다**는 구분이 명확한가

### 수렴자 실측 결과 — 이 주장을 검증하라

수렴자가 Java 17 표준 라이브러리만으로 프레이밍을 구현해 적대적 본문 8종으로 왕복시킨 결과다.

```
written=8 restored=8
  RESULT: all 8 bodies byte-identical round-trip OK
file contains CR byte: yes (from body content only)
```

검증한 본문: 본문 속 닫는 마커 / 본문 속 완결된 가짜 프레임 / `<!--&#32;/msg` / 코드펜스 / 널 문자 / 빈 본문 / 이모지·결합문자 / 본문 내 CRLF.

**이 실측이 C2의 "손상되지 않은 파일은 무손실 왕복" 주장을 뒷받침하는가?** 이 테스트가 **놓치고 있는 케이스**가 있으면 지적하라. (수렴자 주: 소스가 heredoc을 거치며 한글이 U+FFFD로 손상돼, 확정된 것은 바이트 동일성이며 한글 자체 왕복은 §7.10 스모크 테스트로 미룬다.)

## C. C3 — 프로세스 트리 종료 순서

```
C3: <해결 | 미해결>
```

1. **부모가 루프 안에서 종료되지 않는가.** 반복 구간이 자손만 대상으로 하는가
2. 루프 종료 **후에** `taskkill /PID <parent> /T /F` → 실패 시에만 `parent.destroyForcibly()` 순서인가
3. 이 시점에 부모가 살아 있으므로 `taskkill /T` 가 남은 트리를 정리할 수 있는가
4. **보고 범위의 한계**가 명시됐는가 — "생존 PID 없음"이 "전부 종료됐다"가 아니라 "추적한 범위에서 남은 것이 없다"는 뜻임
5. 3라운드에서 네가 제시한 "최소 수정"과 실제 반영 내용이 일치하는가. **다르면 어디가 다른지 적어라**

## D. 최종 판정

- `GO` — C1·C2·C3 모두 착지했다. Phase 1 착수 가능
- `CONDITIONAL` — 착지하지 않은 것이 있다. **C1·C2·C3 범위 안에서만** 나열하라
- `BLOCK` — 수정이 새 결함을 만들었다

머리말의 `판정:` 과 일치시켜라. 1~2문장으로 근거를 대라.
