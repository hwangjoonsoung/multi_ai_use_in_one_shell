## B. E2 — 재동기화 조건 4 되돌림 (중요)

**3라운드에서 agy가 `id == last_id + 1` 연속성 검사를 제안했고 codex도 수용했다. 수렴자가 채택했다가 4라운드에서 실측으로 되돌렸다.**

되돌린 근거는 아래 실측이다. Java 17 표준 라이브러리로 재동기화를 구현하고, id=2 메시지의 헤더를 손상시키되 **그 본문 안에 완결된 가짜 프레임(id=3)** 을 심은 파일로 시험했다.

```
== 엄격 조건 (id == last_id + 1) ==
   id=1 state=OK body=first
   id=-1 state=CORRUPT
   (끝 — 진짜 id=3 복구 실패, 이후 전부 유실)

== 완화 조건 (id > last_id && id < next_id) ==
   id=1 state=OK body=first
   id=-1 state=CORRUPT
   id=3 state=SUSPECT body=FAKE      ← 가짜가 채택됨
   id=-1 state=CORRUPT
```

| 조건 | 가짜 프레임 | 진짜 후속 메시지 |
|---|---|---|
| `id == last_id + 1` | 거부 ✓ | **유실. 복구 0건** ✗ |
| `id > last_id` | SUSPECT로 채택 ✗ | 복구 시도 ✓ |

수렴자의 논거: 손상된 메시지가 통째로 유실되면 `id` 가 건너뛰므로 `last_id + 1` 을 요구하면 어떤 후보와도 맞지 않아 **그 뒤 전부를 잃는다.** 가짜 프레임은 "AI가 완결된 프레임을 출력" + "파일 손상"이 동시에 필요한 희귀 조합이지만, **"손상 뒤 전부 유실"은 모든 손상에서 발생한다.** 따라서 실패 모드를 고르는 문제이고 "전부 유실"보다 "표시된 의심 복구"가 낫다.

```
E2: <동의 | 반대 | 조건부 동의>
```

아래에 답하라.

1. **실측 해석이 맞는가.** `id == last_id + 1` 이 손상 후 전량 유실을 유발한다는 결론이 타당한가. 실측 설계 자체에 결함이 있으면 지적하라
2. **되돌린 판단에 동의하는가.** 동의하지 않으면 두 실패 모드 중 어느 쪽이 왜 더 나쁜지 근거를 대라
3. **문서가 이 한계를 정직하게 적었는가.** "어느 조건을 써도 재동기화는 완전하지 않다"는 기술이 과장이나 축소 없이 사실과 맞는가
4. **제3의 조건이 있는가.** 두 실패 모드를 모두 피하는 방법이 `D12`(외부 Java 라이브러리 금지) 안에서 가능한가. 있으면 구체적으로. **없으면 "없음"이라고 쓰고 넘어가라 — 억지로 만들지 마라**
5. 조건 5(`id < next_id`)와 `room.properties` 의 `next_id` 유지가 여전히 유효한가
