너는 이 프로젝트의 독립 설계 검토자다. **3라운드 — 수정 검증 패스**다.

2라운드에서 blocker 3건이 제기됐고, 그에 대한 수정이 문서에 반영됐다. **이번 라운드는 그 수정만 검증한다.** 새 설계 논의가 아니다.

> **왜 3라운드가 있는가**
> `prompts/consolidate.md` 의 "최대 2라운드"는 **반론 토론**의 상한이다. 같은 쟁점으로 무한히 반박을 주고받지 말라는 규칙이다.
> 이번은 토론이 아니라 **수정이 제대로 착지했는지 확인**하는 별개의 활동이다. 2라운드가 필요했던 이유 자체가 1라운드 수정이 불완전했기 때문이었고(§7.2가 확정 결정과 정반대였다), 이번 수정은 그때보다 규모가 크다. **아무도 검증하지 않은 상태로 구현에 들어가지 않기 위한 패스다.**

## A. B1 — §7.2 호출 프로필

확인 항목을 각각 O/X로 표기하고, X면 무엇이 어긋났는지 적어라.

4. Claude·Codex가 stdin, agy가 인자로 프롬프트를 받도록 표기됐는가 (§6.3과 일치하는가)

## B. B2 — `transcript.md` 길이 기반 프레이밍

**이 규격은 새로 설계된 것이다.** 2라운드에서 방향만 제시됐고 구체안은 검증받지 않았다. 엄격하게 봐라.

```
B2: <해결 | 부분 해결 | 미해결>
```

아래를 구체적으로 판정하라.

1. **임의의 본문이 손실 없이 왕복하는가.** 본문이 `<!-- msg `, `<!-- /msg`, `<!--&#32;/msg`, 중첩 마커, 코드 펜스, 널 문자, 잘린 UTF-8 시퀀스를 포함해도 안전한가
2. **`bytes` 경계 정의가 모호하지 않은가.** 헤더 줄의 개행과 본문 끝의 개행이 각각 본문에 포함되는지 아닌지 한 가지로만 해석되는가
3. **재동기화 절차 4개 조건**(줄 시작 / 헤더 파싱 / 닫는 마커 확인 / `id` 단조 증가)으로 본문 속 가짜 마커를 실제로 걸러낼 수 있는가. **걸러내지 못하는 반례를 만들 수 있으면 제시하라**
4. 쓰기·읽기 구현이 Java 17 표준 라이브러리만으로 가능한가 (`D12`)
5. `D6`(채팅방 기록이 SSOT)과 §7.10의 저장·재개 완료 기준을 만족하는가

**반례를 찾는 것이 이 섹션의 핵심이다.** 깨뜨릴 수 있으면 구체적인 바이트열이나 상황으로 제시하라.

## C. B3 — 프로세스 트리 종료 계약

```
B3: <해결 | 부분 해결 | 미해결>
```

1. §6.3의 **5단계 절차**가 구현 가능한 수준으로 구체적인가. 모호한 단계가 있으면 지적하라
2. **자식부터 종료하고 부모를 마지막에** 종료하는 순서가 옳은가
3. `taskkill /PID <pid> /T /F` 가 `D12`를 위반하지 않는다는 판단이 맞는가
4. **한계 명시가 정직한가.** 실제로는 더 많은 것이 보장되거나, 반대로 여기 적힌 것보다 덜 보장되는가
5. §7.10 완료 기준이 best-effort로 바뀐 것이 §5.2의 `/cancel` Phase 1 포함과 모순되지 않는가
6. §8.4 K4 판정 정정이 적절한가
