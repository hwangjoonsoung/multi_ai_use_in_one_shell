# multi_ai_cli

**Claude · Codex · Gemini(agy) 를 한 화면에서 다루는 에이전트 멀티플렉서.**

세 CLI 를 각자 자기 칸에 띄우고, 한 칸의 답을 다른 칸으로 넘겨 가며 일한다.
AI-1 이 계획을 세우고 AI-2 가 그걸 검증하고 AI-3 가 구현하는 흐름을, 창을 옮겨 다니지 않고 한다.

```
/Users/hj/proj                                    ← 지금 공간
──────────────────────────────────────────────────────────────────
┌ spaces ──────┐ zsh   계획   검증   Codex  [+]   ← 탭. 두 번 누르면 이름 바꾸기
│+ 새 공간      │┏ 계획 ━━━━━━━━━[x]┓┌ 검증 ────[x]┐┌ Codex ───[x]┐
│▸ proj        │┃  Claude Code    ┃│  Claude     ││  codex      │
│  /Users/hj/… │┃  Opus 5         ┃│             ││             │
└──────────────┘┃                 ┃│             ││             │
┌ agents ──────┐┃  ❯              ┃│  ❯          ││  ❯          │
│● 계획         │┗━━━━━━━━━━━━━━━━━┛└─────────────┘└─────────────┘
│  └ Task 조사  │
│● 검증         │  ● 색 점은 관측된 상태 · 아래는 서브에이전트 명부
└──────────────┘
```

**상태**: Rust + PTY 구현이 현행이다(`rust/`). Java 판은 참조용으로만 남아 있다.
설계 의도는 [INTENT.md](INTENT.md), 스펙은 [SPEC.md](SPEC.md) 에 있다.

## 1. 무엇을 하는가

### 각 CLI 를 «그대로» 띄운다

칸 안은 에이전트 자신의 TUI 다. 우리가 흉내 낸 화면이 아니라 진짜 `claude` · `codex` · `agy` 가
PTY 위에서 돌고 있고, 우리는 그 화면을 받아 그린다. 그래서 권한 승인 대화상자, 슬래시 자동완성,
`Esc` 중단, 서브에이전트 표시가 평소 쓰던 그대로 동작한다.

키는 **포커스된 칸의 자식에게 그대로** 간다. 우리 조작은 tmux 처럼 프리픽스(`Ctrl+]`) 뒤로 뺐다.

### 답을 칸에서 칸으로 넘긴다

`Ctrl+]` 다음 `f`. 한 칸의 **마지막 답변 전문**을 꺼내 다른 칸에 인용으로 넣고, 한 문장만 덧붙인다.

```
╭ Claude 의 답 8,412자 (세션 기록) ──────────────────────────╮
│받을 칸  [ ] Codex   [x] Gemini                             │
│한 마디  넌 어떻게 생각해?                                  │
│Tab 이동 · Space 켜기/끄기 · Enter 보내기 · Esc 취소        │
╰────────────────────────────────────────────────────────────╯
```

### 공간(space) × 칸(session)

**공간**은 경로다. 한 공간 안에 칸이 여럿 있고, 칸은 그 경로에서 뜬다. 공간을 바꾸면 다른 공간의
칸은 **죽지 않고 숨는다** — 돌아오면 그대로다. 터미널 칸에서 `cd` 하면 공간이 따라간다.

### 구조화 교차검증 (`--converge`)

같은 안건을 여럿에게 독립적으로 묻고, 답을 **합의 / 이견 / 단독 지적 / 미해결** 로 분류해
`REPORT.md` 를 낸다. 이견이 있을 때만 상대의 반박을 붙여 한 번 더 묻는다(최대 2라운드).
이건 TUI 가 아니라 헤드리스로 돈다 — 대화형에서는 스키마 강제가 안 되기 때문이다.

## 2. 설치

세 CLI 는 **각자의 구독 인증을 그대로 쓴다.** API 키는 필요 없고, 없는 CLI 는 그냥 빠진다.

### macOS / Linux

```bash
# Rust 툴체인이 없으면 먼저
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

./scripts/install.sh          # ~/.local/bin/mai 심링크
```

### Windows

```powershell
# winget install Rustlang.Rustup

.\scripts\install.ps1 -AddToPath     # %LOCALAPPDATA%\mai\bin\mai.cmd 심 + PATH
```

심링크가 아니라 `.cmd` 심을 쓴다. Windows 에서 심링크는 관리자 권한이나 개발자 모드가 필요해
되는 사람과 안 되는 사람이 갈린다. `-AsFunction` 으로 `$PROFILE` 에 함수를 넣을 수도 있고
`-Uninstall` 로 되돌린다. macOS 쪽은 `--alias` · `--uninstall` 이 같은 역할이다.

> ⚠ **`.ps1` 은 아직 Windows 에서 실행 검증하지 않았다.** 작성 환경에 PowerShell 이 없었다.
> Rust 코드 자체는 Windows 타깃으로 `cargo check` 가 통과한다.

## 3. 실행

설치했으면 **어느 디렉터리에서든** `mai` 한 단어다. 빌드가 필요하면 알아서 하고 바로 띄운다.

```bash
cd ~/any/project
mai                   # 여기를 공간으로
mai ~/other           # 다른 디렉터리를 공간으로
```

`mai` 는 **cwd 를 바꾸지 않는다.** 앱이 자기 작업 디렉터리를 첫 공간으로 잡으므로
어디서 쳤는지가 곧 어느 프로젝트인지다. 빌드만 서브셸에서 저장소로 들어간다.

| 하는 일 | macOS/Linux | Windows |
|---|---|---|
| 설치·인증·툴체인 점검 | `mai --doctor` | `mai -Doctor` |
| 참여자를 어떻게 띄우는지 | `mai --which` | `mai -Which` |
| 「cd 따라가기」가 되는 환경인가 | `mai --probe` | `mai -Probe` |
| PTY+VT 파이프라인 점검 | `mai --selftest` | `mai -Selftest` |
| 지금 디렉터리를 신뢰 등록 | `mai --trust` | `mai -Trust` |
| 답 넘기기가 무엇을 꺼내는지 | `mai --quote claude` | `mai -Quote claude` |
| 강제 재빌드 | `mai --rebuild` | `mai -Rebuild` |
| 저장된 방 목록 · 기록 | `mai --rooms` · `--show <ID>` | `-Rooms` |
| 구조화 교차검증 | `mai --converge [@수렴자] <안건>` | 같음 |

Windows 에서 앱 플래그를 **전부 스위치로 연** 것은, PowerShell 이 `--quote` 같은 토큰을
자기 파라미터로 해석하려다 실패하기 때문이다. 사용자가 raw 플래그를 칠 일이 없어야 한다.

스크립트를 직접 부를 수도 있다 — `scripts/doctor.sh` · `rust-build.sh` · `rust-run.sh`
(Windows 는 `doctor.ps1`).

## 4. 조작법

띄우면 **터미널 한 칸**으로 시작한다. 에이전트는 자동으로 올리지 않는다 —
`[+]` 로 필요한 것만 하나씩 붙인다.

> 셋을 늘 다 쓰는 것이 아니고, 안 쓸 참여자까지 켜 두면 칸이 좁아지는 데다 각자 로그인·업데이트
> 안내를 띄워 정리부터 해야 했다. 그래서 **빈 작업대에서 시작해 필요한 것만 붙이는** 쪽으로 잡았다.

| 키 | 동작 |
|---|---|
| 그냥 타이핑 | **포커스된 칸의 자식에게 그대로** 간다 |
| `Shift+Enter` · `Option+Enter` | **줄바꿈.** 전송하지 않고 다음 줄로 (→ §5.1) |
| `Ctrl+A` · `Alt+키` | 자식에게 전달 (줄 처음 이동, 단어 이동 등) |
| `Ctrl+]` 다음 `←/→` · `1..9` · 클릭 | 칸 이동 |
| 탭 **두 번 클릭** | 탭 이름 바꾸기 |
| `[+]` 클릭 | 칸 추가 — 터미널 / Claude / Codex / Gemini 중에서 |
| `[x]` 클릭 | 칸 닫기 |
| 휠 | 커서가 놓인 것만 굴린다 — 사이드바 · 터미널 칸 (→ §5.2) |
| `+ 새 공간` 클릭 | 경로를 입력해 공간 추가. `Tab` 으로 경로 완성 |

프리픽스 뒤의 조작 — `Ctrl+]` 를 누르고 나서

| 키 | 동작 |
|---|---|
| `f` | **답 넘기기.** 이 칸의 마지막 답변을 고른 칸에 인용으로 (→ §5.3) |
| `t` | 터미널 칸 추가 (상자를 건너뛴다) |
| `p` | 칸 추가 상자 (`[+]` 와 같다) |
| `n` | 보이는 모든 칸에 같은 질문을 한 번에 |
| `1`..`9` | n 번째 칸으로 포커스 |
| `q` | 종료 |
| `a` · `]` | `Ctrl+A` · `Ctrl+]` 자체를 **자식에게** 보낸다 |

터미널 본문을 **왼쪽 버튼으로 드래그하고 놓으면 선택한 텍스트가 자동 복사**된다.
선택 영역은 강조되며, `Ctrl+Shift+C` 로 다시 복사할 수 있다. macOS는 `pbcopy`,
Linux는 `wl-copy` / `xclip` / `xsel`, Windows는 `clip.exe` 를 사용한다.
`Cmd+C` 는 바깥 iTerm2가 처리하므로 앱의 선택 복사는 드래그 후 자동 복사를 사용한다.
선택 중 출력은 계속 수신하지만 선택 화면을 고정한다. `Esc`, 다음 입력, 휠 또는 다른 곳 클릭으로 해제한다.
드래그는 현재 보이는 영역 안에서 선택한다. 과거 출력은 먼저 휠로 이동한 뒤 선택한다 (최대 2,000줄).

마우스 추적을 켠 vim 등의 CLI에는 클릭·드래그·버튼 해제·휠을 칸 내부 좌표로 전달한다.
이때 **Shift+드래그**는 텍스트 선택, **Shift+휠**은 로컬 스크롤백이다.
바깥 터미널이 Shift 마우스를 자체 처리하면 해당 터미널의 기본 선택 동작이 적용된다.

`Cmd+V` 등 바깥 터미널의 붙여넣기를 받아 한글·여러 줄을 한 번에 전달한다.
자식이 bracketed paste를 켜면 시작/종료 구분자로 감싸므로 줄바꿈이 즉시 Enter로 실행되지 않는다.
이 모드를 사용하지 않는 셸에서는 여러 줄 붙여넣기가 명령을 실행할 수 있다.
UTF-8 입력, Ctrl 문자, Alt 문자, 수정키+방향키, Home/End, Insert/Delete,
PageUp/Down, F1–F12와 application cursor 모드를 지원한다.

일반 터미널과의 완전 호환은 아니다. IME 조합창과 Option 키의 Meta 설정은 바깥 터미널에 의존하며,
이미지 프로토콜, OSC 클립보드 전달, 확장 키보드 프로토콜의 자식별 협상,
application keypad, 선택 영역의 화면 밖 자동 스크롤은 지원하지 않는다.
대체 화면에는 별도 스크롤백이 없으며 CLI의 자체 스크롤 동작을 따른다.

칸이 넷 이상이면 나란히 두지 않고 **탭**으로 바뀐다. 좁은 칸에 에이전트 TUI 를 밀어 넣으면
자식이 자기 화면을 접어버려 읽을 수 없기 때문이다. `[전체]` 탭으로 다시 한 화면에 모을 수 있다.

**탭 이름은 순전히 사람이 보라고 있는 것이다.** 같은 에이전트를 여럿 띄워 놓고 어느 칸이 무엇을
하는 중인지 구분하려면 제품이 붙인 이름으로는 모자라다. 두 번 누르면 그 자리에서 고쳐 쓴다.

## 5. 알아 둘 것

### 5.1 줄바꿈은 터미널을 탄다

터미널은 예로부터 `Enter` 와 `Shift+Enter` 를 구분하지 않고 **둘 다 CR 하나만** 보냈다.
구분해서 알려주는 터미널에서만 우리가 그 차이를 볼 수 있다. 그래서 두 가지를 한다.

1. 바깥 터미널이 지원하면 **키를 구분해서 달라고 청한다**(kitty 키보드 프로토콜의
   `DISAMBIGUATE_ESCAPE_CODES`). 지원 여부를 먼저 묻고 되는 터미널에서만 켠다 —
   안 되는 터미널에 밀어 넣으면 켜졌다고 착각한 채 응답을 기다린다.
2. `Shift+Enter` 나 `Option+Enter` 가 오면 **`ESC CR`** 로 바꿔 자식에게 넘긴다.

`ESC CR` 을 고른 것은 실측이다 — Claude 입력창에서 `ESC CR` · `CSI 13;2u` · `역슬래시+CR`
셋 다 줄바꿈이 됐고, 그중 `ESC CR` 이 가장 오래되고 널리 통한다.

| 터미널 | `Shift+Enter` | 대안 |
|---|:---:|---|
| iTerm2 · Ghostty · kitty · WezTerm | ✅ | |
| Windows 콘솔 | ✅ 콘솔 API 가 SHIFT 를 직접 준다 | |
| **macOS 기본 Terminal.app** | ❌ 구분 불가 | `Option+Enter` (설정에서 「Option을 Meta 키로 사용」) |

### 5.2 에이전트 칸은 스크롤되지 않는다

우리가 안 보내서가 아니라 **에이전트가 안 받기 때문**이다. 프로토콜대로 좌표를 칸 기준으로 바꿔
넘기고 있고, 받지 않는 자식이면 우리 스크롤백으로 떨어진다. 그런데 바닐라 PTY 에 직접 붙여
재 보면 이렇다.

| | 마우스 추적 | 휠 | PageUp/Down | 화살표 |
|---|:---:|:---:|:---:|:---:|
| Claude | 켬 (`?1000h`~`?1006h`) | 무시 | 무시 | 동작 |
| Codex | **안 켬** (`?1004` 뿐) | 무시 | — | 동작 |

게다가 둘 다 대체 화면(`ESC[?1049h`)에서 돌고, vt100 은 대체 화면에 스크롤백을 두지 않는다
(`Grid::new(size, 0)`). 지나간 출력이 우리 버퍼에도 남지 않는다는 뜻이다.
**지난 내용을 보려면 세션 기록을 봐야 한다** — `mai --quote claude` 가 그 입구다.

터미널 칸은 정상적으로 스크롤된다.

### 5.3 세션은 공유할 수 없다 — 답변만 옮긴다

세 CLI 는 서로 다른 서버·포맷·인증을 쓰고, API 키 경로는 `INTENT.md §3.1` 이 막아 놨다.
그래서 답 넘기기는 세션이 아니라 **답변만** 옮긴다. 꺼내는 곳은 둘이고 순서가 곧 우선순위다.

| 순위 | 어디서 | 한계 |
|:---:|---|---|
| 1 | 에이전트가 남긴 세션 기록 JSONL | 없음. 전문이 그대로 온다 |
| 2 | 우리 화면 버퍼 | 칸에 보이는 만큼 |

확인된 위치는 `~/.claude/projects/<경로>/…jsonl` 과 `~/.codex/sessions/…/rollout-*.jsonl` 이다.
`agy` 는 아직 못 찾아 화면으로 떨어진다. **이 포맷들은 비공개 내부 규약이라 CLI 업데이트로
깨질 수 있다.** 그래서 실패를 오류로 다루지 않고 조용히 2순위로 내려가며, 어디서 몇 자를
가져왔는지 상자 제목에 늘 표시한다.

여러 줄이라 **브래킷 붙여넣기**(`ESC[200~ … ESC[201~`)로 감싸 넣는다. 그냥 쓰면 첫 줄바꿈에서
상대가 전송해 버려 인용문 한 줄만 질문으로 들어간다.

받는 칸은 고를 수 있고 처음엔 나머지가 전부 켜져 있다. 출처 칸은 후보에 없다 —
자기 답을 자기에게 다시 주는 꼴이기 때문이다. 대상 지정에 `Alt+숫자` 를 쓰지 않은 것은,
macOS 터미널이 기본 설정에서 Option 을 Meta 로 보내지 않아 그 키가 아예 안 오는 환경이 있어서다.

### 5.4 공간은 터미널만 움직인다

터미널 칸에서 `cd` 하면 공간 경로가 따라가고, 다음에 붙이는 칸은 거기서 뜬다.
**이미 떠 있는 칸은 자기 경로 그대로다** — 남의 프로세스 cwd 를 바꿀 수는 없다.

에이전트는 공간을 움직이지 않는다. 도구가 잠깐 들어간 디렉터리는 사용자가 옮겨 간 것이 아니다.

Windows 의 PowerShell 은 `Set-Location` 이 셸 안의 위치만 바꾸고 Win32 프로세스 cwd 는
그대로 두는 경우가 있다. 그러면 이 기능이 동작하지 않는다 — `mai -Probe` 로 판정한다.

### 5.5 새 경로에서는 대화상자가 먼저 뜬다

에이전트들은 처음 보는 디렉터리에서 「이 폴더를 신뢰합니까?」를 묻고 답할 때까지 멈춘다.
그때는 우리가 자동 주입한 질문이 그 상자에 먹혀 버리므로, **상자가 떠 있으면 주입을 미룬다.**
사용자 눈에는 「답 넘기기가 안 들어간다」로 보일 수 있는데, 상자를 닫으면 들어간다.

`mai --trust` 로 미리 등록해 둘 수 있다. **보안 결정이라 자동으로는 하지 않는다** —
하는 일은 사용자가 대화상자에서 「예」를 누르는 것과 같고, 대상은 지정한 경로 하나뿐이다.

## 6. 진단

무언가 안 될 때 추측하지 않고 재는 도구들이다.

```bash
mai --probe                    # 셸·pid·cwd 세 고리 중 어디가 끊겼나
mai --which                    # 각 참여자를 어떤 실행 파일로 띄우는가
mai --quote claude             # 답 넘기기가 무엇을 꺼내는가 (전문/화면/실패)
mai --selftest                 # PTY+VT 가 색·한글·와이드 셀을 보존하는가

MAI_KEYLOG=/tmp/keys.log mai   # 받은 키를 그대로 적는다 — 단축키가 안 먹을 때
MAI_DUMP=1 mai --subs claude   # 자식이 뱉는 원시 바이트
```

`--probe` 는 셸을 띄워 `cd ..` 를 보내고 프로세스 경로가 따라오는지 판정한다.

```
== 환경 점검 ==
  플랫폼: macos
  셸: /bin/zsh []
  자식 pid: 39438
  읽어낸 경로: …/multi_ai_use_in_one_shell/rust
  «cd ..» 를 보낸다
  cd .. 뒤:    …/multi_ai_use_in_one_shell
  RESULT: cd 를 따라간다 — 공간 경로가 갱신된다
```

키 이름은 터미널·플랫폼마다 다르게 들어온다. 예를 들어 유닉스의 crossterm 은 `Ctrl+]` 를
`Char(']')` 가 아니라 `Char('5')` 로 준다. `MAI_KEYLOG` 는 그런 것을 바로 드러낸다.

## 9. AI 에게 이 프로젝트의 검토를 맡길 때

`INTENT.md` + `SPEC.md` 두 개만 준다(약 34,600자). 자세한 내용은 [`prompts/README.md`](prompts/README.md).

```bash
P=$(cat prompts/review-request.md)

codex exec --skip-git-repo-check -C . -s workspace-write \
  -c model_reasoning_effort="high" "$P"

agy -p "$P" --add-dir . --model gemini-3.1-pro-high \
  --mode accept-edits --sandbox --disable-slash-commands --print-timeout 10m
```

**에이전트가 리포트 파일을 직접 만든다.** 그래서 쓰기 권한이 필요하다. 대신 프롬프트에서 범위를
좁혔다 — 리포트 1개만 생성, 기존 문서 수정·삭제 금지, 커밋·푸시 금지.

받은 뒤에는 두 리포트를 눈으로 비교하지 말고 수렴 절차를 태운다. **수렴은 CLI 명령이 아니라
Claude 대화창에 말로 요청한다** — `consolidate.md 대로 수렴해줘`.
`consolidate.md` 를 codex·agy 에게 보내면 안 된다. 자기 답안을 자기가 채점하는 꼴이 된다.

| 산출물 | 내용 |
|---|---|
| `codex_review.md` / `agy_review.md` | 개별 검토 응답 (근거로 보존) |
| `codex_review_r2.md` / `agy_review_r2.md` | 2라운드 반론 (이견이 남을 때만) |
| **`REVIEW_REPORT.md`** | **수렴 보고서 — 합의·이견·미해결 분류와 결정 요청** |

> 이 흐름 전체가 `SPEC.md` §7.9 **Phase 3(구조화 수렴)** 의 수동 예행연습이다.
> `--converge` 가 자동으로 해야 할 일을 손으로 하는 것이다.
