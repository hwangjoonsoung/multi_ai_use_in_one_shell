## B. B2 — `transcript.md` 길이 기반 프레이밍

B2: 해결

판정 상세:
1. 임의 본문의 손실 없는 왕복: 본문에 어떠한 이스케이프도 가하지 않고 원시 UTF-8 바이트열을 `bytes` 만큼 직독하므로, 마커 유사 문자열(`<!-- msg `, `<!-- /msg`), 코드 펜스, 널 문자 등이 포함되어도 본문 해석 과정이 없어 완벽히 보존된다.
2. `bytes` 경계 정의: "헤더 줄 개행 직후부터 정확히 `bytes` 바이트"로 정의되어 모호함이 없다. 단, Windows 환경의 CRLF(`\r\n`)와 LF(`\n`) 차이로 인한 검증 실패를 방지하기 위해 파일 저장 시 개행을 LF(`\n`)로 단일 고정함을 구현 가이드에 못박을 필요가 있다.
3. 재동기화 절차 및 반례 제시:
   - [반례 제시 - 손상 본문 속 미래 ID 가짜 마커]:
     손상된 메시지 1(id=0001)의 본문 내에 AI가 대화 예시로 `<!-- msg id=0002 ... bytes=18 -->가짜 본문 예시\n<!-- /msg id=0002 -->` 라는 유효한 형태의 마커 블록을 출력해둔 상태에서 메시지 1의 앞부분 헤더가 손상된 경우를 가정한다.
     직전 정상 복원 ID가 `0000`인 상태에서 재동기화 스캔이 시작되면, 본문 속 가짜 마커는 1) 줄 시작, 2) 헤더 파싱 성공, 3) 닫는 마커 일치, 4) `id=0002 > 0000` (단조 증가) 조건을 모두 만족하여 **가짜 마커가 진짜 메시지 2로 오인 복원**된다. 그 뒤에 실제 진짜 메시지 2(id=0002)가 등장하면 ID 충돌로 인해 진짜 메시지가 버려지는 결함이 발생할 수 있다.
   - [영향 평가 및 완화]:
     이 반례는 "저장 파일 손상"과 "손상된 본문 내 완벽한 미래 ID 마커 예시 존재"가 동시에 결합되어야 하는 극단적 코너 케이스다. 또한 원자적 파일 교체(`atomic replace`)가 기본 적용되므로 일반적인 상황에서 파일 중간 손상 자체가 발생하기 어렵다. 재동기화 시 `id == last_id + 1` 연속성 검사나 `round`, `ts` 필드의 정합성 검사를 보조 조건으로 추가하면 완벽히 차단된다. Phase 1 착수를 막을 수준의 결함은 아니다.
4. Java 17 표준 라이브러리(`D12`) 구현 가능성: `FileChannel` 또는 `InputStream.readNBytes(bytes)` 로 완벽히 구현 가능하며 외부 의존성이 전혀 필요 없다.
5. `D6`(SSOT) 및 완료 기준 만족 여부: 무손실 역직렬화가 보장되므로 완료 기준을 충분히 만족한다.

## C. B3 — 프로세스 트리 종료 계약

B3: 해결

1. 5단계 절차 구체성: 1) 자식 우선 강제 종료 -> 2) 2초 유예 대기 -> 3) 최대 3회 재열거 반복 -> 4) `taskkill /T /F` 실행 -> 5) 생존 PID 오류 표시 및 `/status` 기록의 5단계는 Java 코드로 즉시 옮길 수 있을 만큼 구체적이며 모호한 단계가 없다 (§6.3).
2. 자식 우선 종료 순서의 타당성: 부모 프로세스를 먼저 종료하면 자식 프로세스가 고아(Orphan)가 되어 트리가 단절되고 `ProcessHandle.descendants()` 추적에서 이탈하므로, 리프(Leaf)부터 역순으로 종료하고 부모를 마지막에 종료하는 순서가 기술적으로 정확하다.
3. `taskkill /PID <pid> /T /F` 와 D12 준수 여부: `taskkill.exe` 는 Windows OS 표준 내장 유틸리티이며 Java 표준 `ProcessBuilder` 로 기동하므로 외부 Java 라이브러리 추가를 금지한 `D12` 에 위배되지 않는다.
4. 한계 명시의 정직성: 열거-종료 사이 생성된 프로세스 레이스 컨디션 및 detach된 프로세스의 미보장 한계, 그리고 완전 보장을 위해서는 Job Object(JNA/JNI)가 필요해 Phase 1 범위 밖이라는 점을 솔직하고 정확하게 명시했다 (§6.3).
5. 완료 기준(best-effort)과 §5.2(/cancel)의 정합성: 사용자에게 취소 인터페이스를 제공하되 내부 종료는 최선을 다하고 생존 시 은폐하지 않고 오류로 보고한다는 계약이므로 모순되지 않는다 (§7.10).
6. §8.4 K4 판정 정정의 적절성: 1라운드의 비현실적인 "완벽 대응 가능"을 취소선으로 바로잡고 5단계 절차와 best-effort 한계를 명확히 규정하여 스펙의 신뢰성을 회복했다.

## [범위 밖]

1. **`transcript.md` 개행 문자 규격화**: Windows 환경에서 `\r\n` 이 혼입될 경우 `bytes` 계산 및 닫는 마커(`\n<!-- /msg ... -->`) 매칭에서 1바이트 오차가 발생할 수 있으므로, 파일 쓰기 시 줄바꿈을 반드시 단일 LF(`\n`)로 통일하도록 구현 시 주의가 필요하다.
2. **재동기화 시 `id` 연속성 검사**: B2의 가짜 마커 반례를 원천 차단하기 위해, 재동기화 후보 검증 시 `id > last_id` 뿐 아니라 `id == last_id + 1` 또는 방 메타데이터의 현재 시퀀스 정보와 대조하는 방어 로직을 구현 계층에 권장한다.
